> **Why this page is structured this way:** Daily work gets done because its failure is immediate and visible. Periodic work fails quietly: a quarterly review that slips a quarter, an annual drill that becomes biennial, a figure nobody has re-verified since go-live. So the page is a calendar with an owner against every item, grouped by frequency, with a short section on the ownership model — because the control that makes this work is not the list but the rule that no item exists without a named owner.

## TL;DR

- **An obligation without an owner is the failure mode this calendar exists to prevent.** Alarm on any unowned item.
- **ComplianceSutra holds the regulatory calendar**; this page is the operational superset, including internal items that no regulation requires but whose absence shows up in an inspection.
- **Weekly items are mostly exception and conduct reviews** — overrides, client code modifications, reconciliation ageing.
- **The quarterly re-verification of exchange-set figures is the item most likely to slip** and the one that keeps this manual's numbers from going stale in production.
- **Annual items include the retrieval drill, the manual square-off rehearsal and the data-export test** — three things that are only proven by doing them.
- **Daylight saving is a twice-yearly calendar item with a named owner**, because it moves the <abbr title="Multi Commodity Exchange of India">MCX</abbr> close and everything downstream of it.
- **Every item carries evidence.** A review that happened without a record is indistinguishable from one that did not.

## 1. The ownership model

| Rule | Detail |
|---|---|
| **Every item has a named owner** | A person, not a team |
| A deputy | Named, for leave and departure |
| **Alarm on any unowned item** | The single most valuable control on this page |
| Due date and lead time | Both, so the item surfaces before it is due |
| Evidence | What is retained to show it happened |
| Escalation | Who is told if it slips, and when |
| Review of the calendar itself | Annual: is anything missing, is anything obsolete |
| Joiner, mover, leaver | Items re-owned when a person changes role or leaves |

<Aside type="caution" title="The quarterly re-verification is what keeps the numbers true">
Every figure in this manual — deposits, margin rates, penalty slabs, session timings, lot sizes, file names, expiry days — is circular-driven and will change. The quarterly re-verification is the mechanism that keeps a production configuration from drifting into a historical one. It needs a dated record per figure showing who checked it against which source and when, because "we think it is still right" is not a verification. This item slips more often than any other on the page, and its slippage is invisible until a penalty or a rejection reveals it.
</Aside>

## 9. Exception paths

| Situation | Response |
|---|---|
| An item has no owner | **Assign immediately**; investigate how it was created unowned |
| An item slips | Escalate per its rule; record the slip and the reason |
| An owner leaves | Reassign as part of the leaver checklist |
| A quarterly figure verification is skipped | The configuration may already be stale; verify now and assess what was affected |
| A drill is not run | Reschedule and record; an unrun drill is a finding, especially business continuity |
| A retrieval drill fails | **High-severity**; retention that cannot retrieve is not retention |
| A circular is identified late | Assess what was non-compliant in the interval; report if material |
| The calendar is found to be missing an obligation | Add it; investigate how it was missed; the annual review should have caught it |
| Two calendars disagree | Reconcile; ComplianceSutra holds the regulatory items and must not conflict with this superset |

## Practical notes

- **Alarm on unowned items.** It is one rule and it prevents the whole failure class.
- **Give every item a lead time.** An item that surfaces on its due date is already late.
- **Treat the quarterly figure re-verification as a real task with a dated record.** It is what keeps configuration from drifting into history.
- **Run the three proof-by-doing annual items**: retrieval, export and a live site switch. Each is only true if it has been done.
- **Put daylight saving on the calendar.** Twice a year, entirely predictable, routinely forgotten.
- **Reassign items on every leaver.** Orphaned periodic items are how obligations go quiet.
- **Review the calendar annually.** Obligations are added by circular and the calendar does not update itself.
