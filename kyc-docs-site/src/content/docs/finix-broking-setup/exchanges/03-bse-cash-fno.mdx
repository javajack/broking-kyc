> **Why this page is structured this way:** Most of <abbr title="BSE Limited (formerly Bombay Stock Exchange)">BSE</abbr>'s market mechanics resemble <abbr title="National Stock Exchange of India">NSE</abbr>'s closely enough that repeating them would waste the reader's time. What does not resemble NSE is the connectivity interface and a handful of specific divergences, and those are what break a design built against NSE and extended. So this page is organised as differences: connectivity first, then the mechanical divergences, then the second clearing relationship, which is the cost most often underestimated.

## TL;DR

- **BSE's current interactive interface is BSE <abbr title="Enhanced Trading Interface">ETI</abbr>, the Enhanced Trading Interface** — a session-oriented, high-performance, low-latency interface supporting full trading functionality, drop copy and risk alerts. **The legacy IML interface is discontinued.**
- **A separate ETI session is required per segment**, while **the participant identifier remains the same across segments**. This is a session-management difference, not three separate integrations.
- **ETI supports equity and equity derivatives in production, simulation and disaster recovery**, and also currency and commodity derivatives.
- **API versions are mandated by the exchange.** BSE has required members to move to specified ETI API versions across segments, which makes a version change a scheduled, exchange-driven event rather than a member decision.
- **BSE's weekly index expiry day is Thursday**, following the standardisation effective 1 September 2025 that assigned NSE Tuesday and BSE Thursday.
- **BSE discontinued stop-loss market orders from 9 October 2023**, to contain damage from freak trades — the same reasoning as NSE's 2021 discontinuation for options.
- **Clearing is through Indian Clearing Corporation**, which brings a second clearing relationship with its own reports, collateral norms, deadlines and penalty stream. This is the cost most often underestimated.

<Aside type="caution" title="Check which interface your documentation describes">
BSE has moved from the legacy IML interface to ETI, and IML documentation is still findable. A design or a vendor conversation anchored on IML is anchored on a discontinued interface. Confirm against BSE's current connectivity manual and ETI API manual, and confirm the mandated API version for each segment, before building or certifying.
</Aside>

## 1. Framework

- **BSE ETI (Enhanced Trading Interface)** — the current interactive interface to the BOLT Plus trading system: session-oriented, high-performance and low-latency, supporting full trading functionality, drop copy and risk alerts. **The legacy IML interface is discontinued.** `[not yet in index]`
- **Session model** — **a separate session is required per segment** for ETI-based applications, while **the participant identifier remains the same across segments**. `[not yet in index]`
- **Segment coverage** — equity and equity derivatives in production, simulation and disaster recovery; currency derivatives and commodity derivatives also supported. `[not yet in index]`
- **Market data** — separate market-data interfaces alongside the trading interface. `[not yet in index]`
- **Documentation** — the BSE ETI API manual and the BOLT Plus connectivity manual, published and versioned by the exchange. `[not yet in index]`
- **Mandated API versions** — BSE has required members to adopt specified ETI API versions across segments. `[not yet in index]`
- **BSE membership** — net worth of ₹1 crore for trading member and limited trading member, ₹5 crore self-clearing, ₹15 crore trading-cum-clearing, ₹50 crore professional clearing; deposit-based membership against ₹10,00,000 with ₹1 lakh earnest money; individuals, corporates, partnership firms and limited liability partnership firms eligible. See [exchange membership](/broking-kyc/finix-broking-setup/setup/03-exchange-membership/#4-bse).
- **Stop-loss market orders discontinued** with effect from **9 October 2023**, to contain damage from freak trades. `[not yet in index]`
- **Weekly expiry standardisation** — **Thursday for BSE**, effective 1 September 2025, following <abbr title="Securities and Exchange Board of India">SEBI</abbr>'s circular of 26 May 2025. `[not yet in index]`
- **Indian Clearing Corporation** — clearing rules, report set, acceptable-collateral norms and schedules; for example [<abbr title="Indian Clearing Corporation Limited">ICCL</abbr> notice 20240710-11](/broking-kyc/reference/circulars/clearing-corps/#iccl-20240710-11) (10 July 2024) following [ICCL notice 20240531-3](/broking-kyc/reference/circulars/clearing-corps/#iccl-20240531-3), and the cross-margin counterpart at [ICCL notice 20240426-38](/broking-kyc/reference/circulars/clearing-corps/#iccl-20240426-38).
- **[BSE circulars index](/broking-kyc/reference/circulars/bse/)** — the source documents.

| Capability | Full trading functionality, drop copy and risk alerts |
| **Legacy IML** | **Discontinued** |
| **Session model** | **A separate session per segment** |
| **Participant identifier** | **Common across segments** |
| Segments | Equity and equity derivatives in production, simulation and disaster recovery; currency and commodity derivatives also supported |
| Market data | Separate market-data interfaces |

| **Versioning** | **Exchange-mandated API versions**, applied across segments |

### 2.1 What per-segment sessions actually cost

Less than three separate integrations, more than a configuration flag.

| Dimension | Consequence |
|---|---|
| Session management | A session established, monitored and recovered **per segment** |
| Monitoring | Session state, sequence continuity and latency tracked per segment session |
| Failover | Recovery exercised per segment session |
| Incident scope | **Segment-scoped** — "BSE is down" is rarely the right first statement |
| Capacity | Message rates considered per segment |
| **Certification** | **Per segment**; success on one segment does not transfer |
| Runbooks | Start, stop, recover and verify procedures that name the segment |
| **Version upgrades** | Exchange-mandated, scheduled, and a certification event |

<Aside type="tip" title="Exploit the segment scoping">
Independent sessions per segment give real isolation: an equity derivatives session problem does not have to stop equity trading. Collecting that benefit requires segment-scoped health indicators, segment-scoped client messaging and segment-scoped incident handling. A firm that rolls the segments into one "BSE status" pays for the session management and keeps none of the isolation, and its client communication during an incident will be wrong in a way clients notice.
</Aside>

## 3. Mechanical divergences from NSE

| Dimension | NSE | BSE |
|---|---|---|
| Interactive interface | Computer-to-Computer Link with Non-NEAT Front End; optional Trading Access Point | **BSE ETI**, session-oriented |
| Legacy interface | NEAT identifiers convertible to <abbr title="Non-NEAT Front End">NNF</abbr> | **IML discontinued** |
| Session model | Segments enabled on the connectivity stack | **A session per segment** |
| Participant identity | Twelve-digit identifiers created by the member, reported before use | **Participant identifier common across segments** |
| API versioning | Protocol documents per segment, versioned | **Exchange-mandated ETI API versions** |
| **Weekly index expiry** | **Tuesday** | **Thursday** |
| Stop-loss market orders | Discontinued for options from 27 Sep 2021 | **Discontinued from 9 Oct 2023** |
| Clearing corporation | NSE Clearing | **Indian Clearing Corporation** |
| Report set | NSE Clearing formats and Extranet | ICCL formats and channels |
| Acceptable collateral and haircuts | NSE Clearing norms | **ICCL norms** |
| Member portal | ENIT | BSE member portal |

| Verify per segment before relying on it | Why |
|---|---|
| Order-type and attribute support | Availability differs and changes |
| Freeze thresholds | Exchange-set |
| Price band and surveillance treatments | Exchange-set |
| Session timings and special sessions | Exchange-set |
| Lot sizes and contract specifications | Per contract |
| Position and open-interest limits | Exchange-set |
| Mandated ETI API version | Exchange-set, and enforced |

## 4. The second clearing relationship

The cost most often underestimated, because it is permanent operational load rather than a one-off engineering project.

| Area | Consequence of a second clearing corporation |
|---|---|
| Deadlines | A second deadline chain, with its own bank cut-off arithmetic |
| Reports | A second expected-file checklist, with different names and timings |
| Collateral | A second acceptable-collateral list and haircut schedule |
| Margin files | A second set of risk parameter files to ingest, version and apply |
| Snapshots | Peak-margin snapshots per clearing corporation |
| Reporting | Margin reporting per clearing corporation |
| Penalties | A second penalty stream to reconcile and attribute |
| Settlement | A second settlement operating path |
| Cross-margin | ICCL's own cross-margin treatment |
| Treasury | Funding split across two clearing relationships, with composition monitored at each |

## 5. Operational consequences

| # | Consequence | Response |
|---|---|---|
| 1 | Certification is per segment | Plan against the published calendar, segment by segment |
| 2 | Runbooks name the segment | Not a single document with conditionals |
| 3 | Segment-scoped incidents | Health indicators, alerts and client messaging all segment-scoped |
| 4 | **Two concentration days a week** | NSE Tuesday and BSE Thursday; capacity and staffing cover both |
| 5 | Two clearing deadline chains | Both counted backwards from their own bank cut-offs |
| 6 | Two file checklists | Asserted independently |
| 7 | Two collateral regimes | Eligibility and haircuts applied per clearing corporation |
| 8 | Two penalty streams | Attributed and reconciled separately |
| 9 | **Exchange-mandated API version changes** | Scheduled, tested and certified; not a member decision |
| 10 | Cross-exchange client view | Clients see one account; obligations are per exchange and segment |
| 11 | Smart order routing | Would require approval and demonstrable best execution; deferred at Finix |

## 7. Exception paths

| Situation | Response |
|---|---|
| One segment session down | Stop that segment only; the others continue; **say so precisely** in client messaging |
| A segment certified, another not | Enable only the certified segment |
| **Exchange mandates a new ETI API version** | Schedule, test in simulation, certify, and cut over before the effective date |
| Connection rejected after a version deadline | The mandated version was not adopted; this is foreseeable and should not happen |
| ICCL collateral norms change | Apply to BSE-cleared collateral; NSE-cleared collateral follows NSE Clearing's norms |
| Thursday expiry concentration | Capacity and staffing planned; it is predictable |
| Client sees one balance, two obligations | The client view must make the per-exchange obligation visible |
| A design change made for NSE assumed to apply to BSE | **Verify per segment**; the assumption is the recurring defect |
| Second clearing relationship's deadline missed | Same escalation as the first; the consequence path is the same |
| BSE portal unavailable at a submission deadline | Document attempts; escalate to the exchange; retain the evidence |

## Practical notes

- **Confirm you are building against ETI, not IML.** IML documentation is still findable and the interface is discontinued.
- **Track the mandated ETI API version per segment.** The exchange sets it and enforces it; a missed upgrade is a rejected connection.
- **Keep health, alerting and messaging segment-scoped.** It is how you collect the isolation you are paying for.
- **Budget the second clearing relationship as operational load, not an engineering task.** It is permanent and it lands on operations.
- **Plan for two concentration days.** Tuesday and Thursday now both carry expiry weight.
- **Verify every assumption per segment.** "It works on NSE" is the recurring source of BSE defects.
- **Keep ICCL and NSE Clearing collateral treatments separate.** They are different lists with different haircuts.
