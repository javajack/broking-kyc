> **Why this page is structured this way:** An inspection is a sequence of questions, and a firm is ready to the extent that each question has a known answer with known evidence and a known owner. So the page is organised as the question set — grouped by what inspections are actually testing — with the location of each answer. The self-inspection drill follows, because readiness is only proven by rehearsal, and the common findings section is last because it is the most useful diagnostic: almost every finding traces to one of a small number of root causes.

## TL;DR

- **Readiness is a property of normal operation, not a project.** Evidence produced as a by-product of doing things properly is available immediately; evidence assembled before an inspection is visibly assembled.
- **Thirty-odd questions cover most of an inspection**, and each has a known answer, a known artefact and a known owner. Section 2 is that list.
- **The four artefacts asked for first** are the [configuration baseline map](/broking-kyc/finix-broking-setup/compliance/01-compliance-config-baseline/), the [pre-trade check ladder](/broking-kyc/finix-broking-setup/rms/03-pretrade-check-ladder/), the policy set, and the registers.
- **Run a self-inspection annually** using the real question set and the real evidence path, timed. A question that takes a day to answer in a drill takes a day in an inspection.
- **Most findings trace to five root causes**: an unowned obligation, a misclassified value, a configuration that drifted from a policy, an ageing exception queue, and an untested retrieval.
- **Answer what is asked.** Volunteering adjacent material lengthens the inspection and raises questions nobody had.
- **A known breach reported is handled differently from one discovered.** Report before the inspection finds it.

## 2. The question set

|---|---|---|

## 4. The self-inspection drill

| Element | Detail |
|---|---|
| Frequency | **Annually**, and in week four after go-live |
| Method | Use the **real question set** in section 2 and the real evidence path |
| **Timed** | A question that takes a day in a drill takes a day in an inspection |
| Independent | Run by someone who did not build the thing being tested; internal audit is the natural choice |
| Sampling | Real clients, real dates, real orders — not prepared examples |
| **Hardest questions first** | "Why was this order released", "why was this client squared off", "produce a contract note from six years ago" |
| Output | A findings list with dated actions and owners |
| Closure | Tracked; **an unclosed action from the last drill is the first finding of the next** |

<Aside type="caution" title="Use real samples, chosen by the person running the drill">
A self-inspection using examples the team selected is a demonstration, not a test. The value comes from a sample the operator did not prepare: a client picked at random, an order from an arbitrary minute, a date six years back. If the answer comes quickly, the firm is ready. If it requires a query to be written, a vendor to be called, or a backup to be restored, the firm has found exactly what an inspection would find, with time to fix it.
</Aside>

## 5. During an inspection

| Practice | Detail |
|---|---|
| Single point of contact | Compliance coordinates; others do not respond directly |
| **Answer what is asked** | Volunteering adjacent material lengthens the inspection and raises new questions |
| Accuracy over speed | A wrong answer corrected later is worse than a considered one |
| **Log every request and response** | What was asked, what was provided, when, by whom |
| Produce from the system | Not from a spreadsheet prepared for the purpose |
| **Report known breaches** | Before the inspection finds them; this is handled differently |
| Do not speculate | "I will confirm and revert" is a complete answer |
| Escalate internally | Senior management informed of scope and direction |
| Working space | Separate, with controlled access |
| After | Findings, responses, remediation plan with dates and owners, closure tracking |

## 6. Common findings and their root causes

| Finding | Root cause | Prevention |
|---|---|---|
| A value in use is not in any approved policy | **Configuration drift from policy** | Monthly diff of deployed against the approved register |
| A discretionary value is described as regulatory | **Misclassification** | The classification column, reviewed |
| An obligation was not filed | **An unowned obligation** | Alarm on unowned calendar items |
| Reconciliation exceptions aged | **Measuring count, not age** | Age of the oldest open item as the metric |
| A record could not be produced | **Untested retrieval** | The annual retrieval drill |
| Square-off thresholds differ from the disclosed policy | **Policy-mirror drift** | Change request requires the policy version |
| A terminal was used before reporting | Procedural gate rather than a technical one | Routing gated on the reporting reference |
| A certification lapsed and the person continued | A report instead of an action | Automatic deactivation on expiry |
| Screening results without a list version | Missing field | Mandatory list version with every result |
| An alert population with no dispositions | Capacity, or no workflow | Open-alert ageing as the metric |
| A client traded without a registry record | A bypassed gate | Alarm on activation without a record |
| Contract notes issued on unreconciled trades | Deadline pressure overriding the gate | The gate enforced in code |
| Client funds in a non-client account | Gateway settlement configuration | Daily account-level assertion |
| Board accountability not evidenced | Pack produced without minutes | Minutes as the evidence |

The pattern is visible: almost every finding is one of **unowned**, **misclassified**, **drifted**, **aged**, or **untested**. A firm that builds controls against those five words prevents most of the list.

## 8. Exception paths

| Situation | Response |
|---|---|
| A question cannot be answered from the system | Note it; answer as fully as possible; **treat it as a finding to fix** |
| A record cannot be retrieved | High severity; escalate internally; be straightforward with the inspector |
| A breach is identified during preparation | **Report it before the inspection finds it** |
| An inspector asks about an area with no evidence | Say so; produce what exists; remediate |
| A finding is disputed | Respond factually with evidence; do not argue without it |
| Remediation cannot be completed in the stated time | Propose a dated plan rather than missing a commitment |
| A self-inspection fails badly | Treat it as the gift it is; dated actions; re-run after remediation |
| An unclosed action from the previous drill appears | It is the first finding; close it |

## Practical notes

- **Maintain the evidence pack continuously.** The difference between produced and assembled is visible within minutes.
- **Run the drill with samples the operators did not choose.** Anything else is a rehearsal of a performance.
- **Time the drill.** Slow is the same as absent when there are twenty more questions.
- **Build controls against the five words**: unowned, misclassified, drifted, aged, untested.
- **Report known breaches first.** The handling is materially different.
- **Answer what is asked.** Helpfulness lengthens inspections.
- **Close the actions.** An unclosed action is the finding that compounds.
