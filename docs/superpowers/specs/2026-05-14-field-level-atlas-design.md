# Field-level Data Flow Atlas — Design

**Date:** 2026-05-14
**Sub-project:** #3 of the broking-ops expansion
**Status:** Design — pending user review

## Context

Four sub-projects have shipped this session:
- #1 Circulars Refresh — 884 entries across 13 issuer groupings.
- #2 Vendor Atlas — 233 named products across 22 categories.
- #7 Compliance Blueprint — 400 verifiable touchpoints across 16 domains.
- #6 Broker Process Narrative — 8.2K-word continuous explainer from ACTIVE through lifecycle events.

The site has a canonical field listing at `kyc-docs-site/src/content/docs/reference/master-dataset.md` (30 sections A–AC, ~454 fields with data types, sizes, validations). Master-dataset answers "what fields exist and how are they shaped". It does **not** answer "where does each field flow, in what format, with what frequency, with what transformation". That is sub-project #3.

## Goal

A bidirectional **Field-level Data Flow Atlas** at `kyc-docs-site/src/content/docs/reference/field-atlas/` that maps every field's full downstream trajectory — KRA, CKYC, exchange UCC, depository BO, back-office, RMS, contract notes, regulatory reports, DLT comms, FATCA/CRS, AML/FIU — with field-name-at-destination, length/format, update frequency, transformation rule, and quirks/notes per field-destination relationship.

## Output

### Pages

- `reference/field-atlas.md` — overview landing page (TL;DR, stats, navigation hub, link to master CSV).
- `reference/field-atlas/sections/<section-slug>.md` — **30 per-section sub-pages** (one for each of master-dataset sections A–AC). Each shows that section's fields with downstream destinations.
- `reference/field-atlas/destinations/<destination-slug>.md` — **14 per-destination sub-pages**, one per destination system. Each shows the fields that destination consumes, sourced from various master-dataset sections.

### Asset

- `kyc-docs-site/public/field-atlas-master.csv` — master CSV with ~2,000+ field-destination rows; downloadable from the overview page. Regenerated by build script on every refresh.

## 14 destinations covered

1. **KRA** — common upload template used by CVL, NDML, DOTEX, CAMS, KFintech
2. **CKYC** — CERSAI templates T1 (Individual) / T2 (Minor) / Legal Entity
3. **NSE UCC** — Unique Client Code registration via REST API / batch file
4. **BSE UCC** — via BEFS (BSE Electronic Filing System); Unfreeze for post-registration changes
5. **MCX UCC** — pipe-delimited 2-rows-per-client format, with commodity-category and income-proof fields
6. **CDSL BO** — fixed-length lines 01–07; 16-digit BO ID (DP8 + Client8)
7. **NSDL BO** — UDiFF ISO-tagged (adopted Mar 2024); "IN" + 14 chars BO ID
8. **Back-office** — vendor-neutral typical fields for ledger, contract note, brokerage computation, statement of accounts
9. **RMS** — margin computation inputs: segment, position, risk-attributes, available-margin envelope
10. **Contract Notes / ECN** — SEBI-prescribed format with ICAI-aligned columns
11. **Regulatory reports** — DMF (Daily Margin File), CFR (Client Funding Report), peak margin reports — per clearing-corp file specs
12. **DLT comms** — SMS + email template fields per TRAI DLT framework (header / template ID / variable slots)
13. **FATCA / CRS reports** — annual format via KRA centralization (post Feb 2024 SEBI circular)
14. **AML reports to FIU-IND** — STR / CTR / CCR / CBWTR via FINnet 2.0 XML

## Per-row schema

Every row in the master CSV (and equivalently every row in any markdown table on the per-section / per-destination pages):

| Column | Description |
| --- | --- |
| `source_section` | Master-dataset section ID (A–AC) |
| `source_section_name` | Human-readable section name |
| `field_id` | Canonical field ID from master-dataset (e.g., `A-pan_number`, `G-bank_account_no`) |
| `field_name` | Human-readable field name |
| `destination` | One of the 14 destinations (closed vocabulary) |
| `destination_field_name` | Field's name at the destination if different (else `[same]`) |
| `destination_format` | Length/type at destination (e.g., `CHAR(10)`, `VARCHAR(80)`, `DATE YYYYMMDD`) |
| `frequency` | When this field flows: one-time / on-modify / daily / on-trade / EOD / on-event |
| `transformation` | Any change between source and destination: `[direct]` / `uppercase` / `concat with X` / `truncate to N` / `derived from Y` / `null-if-Z` |
| `quirks_notes` | Destination-specific gotchas (e.g., "MCX requires uppercase; rejects mixed-case names") |
| `spec_source` | Citation to circular ID or vendor doc URL where the format is verified; `[industry typical]` if no public source |

## Workflow

### Agent dispatch — 6 clustered agents

| Agent | Cluster | Destinations | Approx output rows |
| --- | --- | --- | --- |
| A | Identity registries | KRA + CKYC | ~150–250 |
| B | Exchange registration | NSE UCC + BSE UCC + MCX UCC | ~150–300 |
| C | Depository BO opening | CDSL BO + NSDL BO | ~120–200 |
| D | Internal systems | Back-office + RMS | ~200–350 |
| E | Computed flows | Contract Notes + Regulatory Reports (DMF/CFR/peak-margin) | ~80–150 |
| F | Comms + financial intelligence | DLT comms + FATCA/CRS + AML/FIU | ~80–150 |

Each agent receives:
- Path to `master-dataset.md` for canonical field IDs and section structure.
- Path to relevant circulars sub-pages from sub-project #1 (e.g., for KRA agent, paths to `circulars/cersai.md`, `circulars/sebi-mirsd.md`).
- Closed vocabulary of destination slugs.
- Per-row schema with explicit column list.

Agent output: pipe-delimited rows in `working/field-atlas/<cluster>.psv`. PSV (pipe-separated values) is used because CSV escaping is fragile with markdown / regulatory text. Header row included.

### Consolidation — 2 Python scripts

1. **`working/build_field_atlas_data.py`** — concatenates the 6 PSV files, deduplicates exact-row duplicates, validates schema conformance, writes the master CSV to `kyc-docs-site/public/field-atlas-master.csv` and also a working copy at `working/field-atlas-master.psv` for downstream pages. Reports stats (rows by destination, rows by section, orphan field IDs not matching master-dataset).

2. **`working/build_field_atlas_pages.py`** — reads the master CSV, emits:
   - The overview page `reference/field-atlas.md`.
   - 30 per-section sub-pages under `reference/field-atlas/sections/`.
   - 14 per-destination sub-pages under `reference/field-atlas/destinations/`.
   - Each page follows the project documentation conventions (TL;DR → why-this-order → conceptual overview → tables → practical notes → verified-through).

## Documentation conventions

Each page follows the project's conventions established in sub-projects #1, #2, #6, #7: source traceability (every row cites a spec source where possible), reasoned doc structure (per-section pages grouped by master-dataset's existing A–AC order; per-destination pages grouped by domain), high-level → low-level (TL;DR → overview → tables), alternatives surfaced where relevant (e.g., NSE-UCC REST vs batch; CDSL fixed-length vs UDiFF migration discussion), practical notes per page, vendor-naming policy (back-office is intentionally vendor-neutral on the per-destination page, since the Vendor Atlas is where products live), field-level baseline (this IS the field-level baseline).

## Risks

- **Rate limit at 6 agents** — below the historical threshold; safe.
- **Format specs not publicly accessible** — back-office and RMS in particular are vendor-specific. Mitigation: agents describe typical fields based on master-dataset and operational use; rows tagged `[industry typical]` for transparency.
- **Field-ID drift** — if a field appears under a different ID across cluster agents, the build script flags it as an orphan. Resolution: re-run with corrected ID, or accept the row in the master CSV with an "ID not in master-dataset" annotation.
- **Page-count growth** — 45 new pages plus the CSV. Astro Starlight handles it; sidebar density mitigated by collapsed groups.
- **CSV escaping** — using PSV internally avoids most issues; final CSV emission uses Python's `csv` module with QUOTE_ALL for safety.

## Out of scope

- Modifying `master-dataset.md` itself — atlas references it; doesn't replace.
- Vendor-specific field mappings beyond category (e.g., TechExcel's exact column names) — that's per-vendor integration documentation, deferred.
- Runtime audit-trail / data lineage — that's master-dataset Section Z; atlas is a design-time mapping.
- File transmission mechanics (SFTP, leased line, REST endpoints) — destination has a row per field; how those rows are physically delivered is a separate concern.

## Success criteria

- 1 overview page + 30 per-section sub-pages + 14 per-destination sub-pages + 1 master CSV.
- ≥ 1,500 unique field-destination rows in the master CSV.
- Every row has all 11 schema columns populated (no blanks).
- ≥ 90% of rows have a non-`[industry typical]` spec source.
- Sidebar updated with collapsed "Field Atlas" group.
- Astro build clean.
- CSV downloadable from the overview page.
